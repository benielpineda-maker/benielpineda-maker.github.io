RAG Transcript Assistant

Problem
Hundreds of call transcripts sat in a Drive folder nobody read. Finding out whether three customers complained about the same thing meant opening thirty documents — and a general chatbot couldn't help, because it had never seen them.
Approach
Transcripts are chunked with overlap, embedded, and stored in a Qdrant vector store with metadata on every chunk. One ingestion workflow writes; three query surfaces read — a secured web API, a document-listing endpoint, and a Google Chat bot.
Result
The team asks questions in plain language and gets answers grounded in the actual transcripts, each traceable back to its source file — with the model required to say so when it finds nothing relevant.

Data pipeline · Cloudflare + SQL + TypeScript

Medallion Marketing Data Pipeline

Problem
Raw data arrived from several sources in different shapes, and re-running an import duplicated records. With no separation between raw and reporting data, one bad load corrupted the numbers everyone relied on.
Approach
Bronze → Silver → Gold on Cloudflare: pluggable extractors land raw data in R2 untouched, SQL conforms it into a D1 warehouse, and Gold views expose clean marts. Serverless, scheduled, and idempotent by design.
Result
Reporting reads from a stable Gold layer, loads can be safely re-run, and bad source data can be corrected and replayed from Bronze without rebuilding the pipeline.

Build notes

Decisions from real builds — the things that separate an automation that demos well from one that's still running six months later.

Chunk overlap is not optional

Splitting transcripts into fixed-size chunks will eventually cut a sentence in half, and whatever was in that sentence becomes unretrievable. 100 characters of overlap costs a little storage and saves answers that would otherwise silently go missing.

Make retrieval mandatory, and "I don't know" allowed

A RAG agent left to its own judgement will sometimes skip the search tool and answer from the base model's general knowledge — confidently, and wrongly. The system prompt has to force the lookup and explicitly permit the agent to report that nothing relevant was found.

Assume every re-run will happen twice

Triggers fire twice, loads get replayed, someone clicks the button again. Every pipeline I build gets a dedupe guard or an idempotent write, because the alternative is discovering duplicate records weeks later in a report nobody trusts any more.

One primary path, two fallbacks

In the résumé-intake workflow the preferred source — a download link — fails often enough to matter. Falling back to the email attachment, then to parsing inline text, is the difference between losing applications and not.

Constrain AI output to a schema

Free-text model output can't be written to a spreadsheet or a database without parsing that breaks the first time the phrasing changes. Forcing a structured JSON response makes the result usable by the next node instead of by a human.

A silent bot reads as a broken bot

Retrieval plus generation takes several seconds. The Google Chat bot posts a placeholder immediately and then edits that same message with the answer — instant feedback, without leaving two messages cluttering the thread.

Design around the free tier before you need to

The competitive-intelligence workflow runs on free-tier LLM and search APIs, which means batching, pacing requests, and handling rate-limit responses as a normal outcome rather than an error. It also means the workflow still works for someone importing it with no budget.
